    Every user edit takes the edit route¶

    Context.

    • Most structure edits go through Editor. An Editor action gives undo, and its validation reason marks the graph unsaved. Value edits did not go through Editor: card and stage widgets, the Ports panel, settings rows and skin controls wrote the model directly. A few structure edits skipped it too: the edge propagation toggle, port reorder, and the promote/demote fallback in render_settings.
    • So access checks, the unsaved mark and undo were added one write path at a time, and a path that missed that wiring missed all three. A gate object per write path (ADR 0051) was that wiring.
    • Two skin controls showed the result: the stacked skin's fold toggle and the annotation's text edit mark nothing unsaved (they only redraw the card, which is visual-only) and are not undoable.
    • The goal is that a developer of nodes, widgets and skins gets correct access and unsaved marking without writing any code for it. Access tiers guard against accidents, not malice (ADR 0027).

    Decision.

    • A user edit and the edit route. A user edit is one change a person or an agent makes to something a document saves: a value, a setting or the structure. EditRoute (haywire.core.graph.edit_route) is the way a user edit reaches Editor; the one writer that still goes around it is listed under Consequences. It is per session and per level, and reads the level's Editor and its level mode through two callables at every call, so it follows a level whose Editor is swapped and refuses a write the moment the mode drops. It knows nothing about levels or locks. Measured node sizes are derived from the browser's layout and stay outside the route.
    • Each write names its minimum. set_port, set_setting and reset_setting take a required minimum: LevelMode: card and stage widgets pass operate, the Ports panel and Properties forms pass edit. A write below it returns False and changes nothing.
    • Level mode. LevelMode (haywire.core.access, beside AccessTier) is view < operate < edit, the mode a session works one level in. The graph editor builds one route per level and session, whose mode callable is level_mode (haybale_graph_editor/access.py): edit when the session's real tier and the lock allow edit, operate when they allow operate, else view. Every graph-editor check reads that route and nothing else: canvas handlers (@handles_event(requires=LevelMode)), accepts_command, menus, the selection toolbar, the inspector polls (can_edit_graph) and SessionContext.level_mode. Farmhand builds a route with the tool's mode; agents have no level and no lock. A route is an ordinary per-level object, not a DI registration.
    • The browser layer. Superseded by ADR 0060: the browser projects the route through one data-hw-requires stamp and the server's handler table, and AccessGate owns the gate. The route is still the refusal that counts.
    • Routed widget models. A widget sees a WidgetModel. The host (card, stage, Ports panel, settings row) passes its route to the widget factory, which builds a SettingWidgetModel that reads the cell and sends each write through the route: a promoted port's write goes to its setting, any other to the port. A widget rendered with no route gets a model that refuses every write. Widget code does not change: set_value and bind() show the model's value again when the write is refused. A compound widget wraps the model it was given, so it is routed too.
    • A skin draws, widgets write. A skin writes nothing; every control on a card is a widget that writes through the card's route. BaseSkin._render holds the route per node id for one render (skin instances are app-wide singletons), render_widget draws a port's widget, and render_setting_widget(bag, name, node_id, *, widget_key=None) draws a settings field's widget through the same routed model. The fold header is a FoldWidget the FOLD type declares (set on every fold port by FOLD._configure_port, a saved one included), and a fold value change redraws its card, so an undo or an agent's write redraws too. The annotation's text is a NoteTextWidget on the text setting, which keeps the double-click editor.
    • operable=False. A port (DataPort.operable) or a settings field (setting(..., operable=False)) may declare that operating its widget may not change it. The route enforces it: a write to such a target needs level mode edit whatever its minimum, so every surface, Farmhand included, gets the rule. The widget is stamped data-hw-requires="edit" (ADR 0060). A promoted port inherits it from its setting. The annotation's text declares it. It is a boolean, not a tier.
    • render_settings(route=). The route is a required keyword. Every edit, reset and set-to-none a row makes goes through it at level mode edit; route=None is for a bag no graph level owns (a run's settings), whose rows write the bag directly. A bag no document saves, such as a multi-selection's neutral form, is written directly after the mode check.
    • Structure edits go through route.editor(). It returns the level's Editor only in level mode edit, and None below it. The verbs stay on Editor, unmirrored. The canvas manager holds the route instead of the Editor, and route_for(context) returns the route of the level on screen. Port reorder, edge propagation and promote/demote are Editor actions, so they are undoable.
    • The unsaved rule, by mechanism. An edit marks unsaved the document that saves the changed value, and only when what the field stores changed: (is_locally_set, value) for a setting, the own value for a port. A node bag or port write calls NodeWrapper.mark_value_edited(). A graph or edge bag write (graph props, graph metadata, edge style) calls the graph's mark_graph_dirty(ChangeReason.GRAPH_CONTENT_CHANGED). A Group interior's edit marks its host through GraphNode's forwarding; a placement's interior is runtime state that no document saves (ADR 0038), so it marks nothing.
    • Value writes are recorded in level mode edit. The route passes record=True to the Editor value verbs only when its level mode is edit. Below that the write is applied and marks unsaved, then an undo fence is added, which ends any merge run; a write that changes nothing adds no step and no fence, and keeps the redo branch. A multi-node form edit is one SetSettingsAction or ResetSettingsAction (route.set_settings, route.reset_settings), a composite of the per-bag setting actions.
    • A merge run. Consecutive writes by one route to one field amend a single undo step, so a slider drag or a typed word is one step. The run ends at another step on the history, a fence (an unrecorded write, a canvas gesture, a Farmhand call, a save), an undo or a redo, or VALUE_EDIT_MERGE_IDLE_S (3 s) after the step's last write. The route object is the session token in the merge key, so two sessions never merge and each Farmhand call builds its own route. A reset never amends and is never amended. A run that ends on its start value keeps its step, whose undo then changes nothing visible: the rule is the same for every field, and no step is ever removed after it was recorded.
    • Value steps amend the run's own step; they do not use the history merge. HistoryManager holds the step add_value_action last recorded or amended, and amends it only while it is still the pending tail, else the history tip (the last action of a group); any other action, a fence, an undo, a redo or clear() drops it. The run is held explicitly rather than read off the history's shape, because after a redo the redone step is the tip with nothing redoable, so it looks like an open run. The generic merge cannot serve a drag: it has a 100 ms window, looks at pending actions only, and the grouping window flushes the step to the history after 500 ms, so the later ticks of a longer drag would start new steps. The amend adopts the newer value into the step without executing it, so the step stays the executed action it was.

    Considered options.

    • A gate per write path (one for a node's writes, one for the graph's, one on each widget, and a forwarder inside compound widgets). Replaced: each path had to remember to ask, and one that forgot skipped access, unsaved and undo together.
    • A route that mirrors every Editor verb. Rejected: about 28 structure verbs would be duplicated for one check. Handing out the Editor only in level mode edit gives the same refusal in one place.
    • A protocol in core with the class in the graph editor library. Rejected: the route has one implementation and Farmhand needs it too. The only policy that reaches core is the mode callable.
    • A generalized history merge for value edits. Rejected: it would change the behaviour of every mergeable action.
    • Begin and end gestures on widgets. Rejected: typing has no natural end.
    • A check of who is writing, at the cell. Rejected: a cell has no session or level, and workers and edges write the same cells. The check belongs where a user edit enters.

    Consequences.

    • Node, widget and skin authors write no access or unsaved code. A widget gets both from the model its host built; a skin draws its controls as widgets.
    • One user edit still writes directly, so it marks nothing unsaved and is not undoable: the pin menu's widget-visibility choice for a promoted port, which is kept in the promotion record rather than in a settings field and has no Editor verb. The pin menu checks level mode edit before writing it.
    • A fold toggle and an annotation text edit are undo steps in level mode edit and mark the graph unsaved. A fold toggles from operate on; the annotation's text needs edit.
    • A host that renders a widget or a settings row must pass a route, or the widget is read-only. Forgetting fails closed.
    • Graph props and graph metadata now mark the graph unsaved, so closing a graph after editing one warns.
    • Value edits in level mode edit are undoable, as are structure edits made through route.editor(). A multi-node form edit is one step.
    • The history is shared by every session on a graph, so one session's undo can undo another session's step.
    • Properties panels show only in level mode edit, so a settings row or a Ports-panel widget has no read-only rendering. The route still refuses a write below the mode it needs (ADR 0051).
    • Code that deliberately writes the model directly goes around the route and is outside what the tiers promise.
