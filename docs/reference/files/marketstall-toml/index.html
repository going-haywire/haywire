    marketstall.toml¶

    Location: the repo root — one file per publishing repository.

    Owner: haywire share. Regenerated in full on every publish; never hand-edited.

    A marketstall is one author's published feed: a flat list of [[haybales]] rows, one per library, that consumers subscribe to by URL. Each row is mostly a verbatim copy of that library's haybale.toml, plus the coordinates a library cannot state about itself.

    Because most of a row is copied, the fields' meanings are documented once, in haybale.toml. This page covers what is added at publish, and which fields travel how.

    The same [[haybales]] row schema appears in three places: here, in the global marketplace's inline section, and in the project cache — see marketplace.toml.

    The file¶

    # marketstall.toml — share this file's raw URL so others can subscribe.
# Regenerated by `haywire share`; every row is rewritten on each publish.
#
# ╔═══════════════════════════════════════════════════════════════════════════╗
# ║ MOST OF A ROW IS NOT SHOWN HERE.                                          ║
# ║                                                                           ║
# ║ Every row also carries the descriptive fields copied verbatim from the    ║
# ║ library's haybale.toml — id, label, description, tags, os, on_reload,     ║
# ║ linked_libraries, origin, origin_provider, notes, examples_path,          ║
# ║ tests_path, the three *_url fields, repeatable [[authors]] tables, and a  ║
# ║ [deprecated] table when the author declared one. They mean exactly what   ║
# ║ they mean there, and are documented there, once:                          ║
# ║                                                                           ║
# ║     docs/reference/files/haybale-toml.md                                  ║
# ║                                                                           ║
# ║ Shown below are only `require`, projected from pyproject's [project]      ║
# ║ dependencies, and the fields the publisher generates because a library    ║
# ║ cannot state them about itself. `name` and `version` are canon in         ║
# ║ haybale.toml and merely copied here.                                      ║
# ╚═══════════════════════════════════════════════════════════════════════════╝

[[haybales]]
name              = "haybale-core"

# ── copied from haybale.toml, which is canon ────────────────────────────────
# Owned by the release machinery, which writes it to haybale.toml and syncs the
# generated copy into pyproject.toml. Not a floor and nothing resolves against
# it: its only job is the update comparison against what is installed.
version           = "0.0.40"

# ── projected from the library's pyproject.toml ─────────────────────────────
# The framework floor, projected from [project] dependencies as a full PEP 508
# token. An absent key means undeclared; the bare name "haywire-core" means
# declared with no floor. Those are different answers, which is why the field
# carries the package name and not just the specifier.
require           = "haywire-core>=0.0.39"

# ── generated: the coordinates a library cannot state about itself ──────────
# Passed verbatim to `uv pip install`. Tag-pinned by the share pipeline, so it
# names the exact commit a consumer gets. This is the row's ONLY ref — every
# declared path resolves against it, so no two fields can disagree about which
# commit was published.
install_spec      = "haybale-core @ git+https://github.com/going-haywire/haywire.git@v0.0.40#subdirectory=barn/haybale-core"
# "git" (share wizard) or "pypi" (CI publishing script). Drives install
# routing and the version-fetching strategy. A row read from a haybale.toml on
# disk carries "local" instead, but such a row is never published.
source            = "git"

# ── plus every copied field; see the block at the top ───────────────────────
label             = "Core"
description       = "Fundamental components for haywire graphs"
origin            = "https://github.com/going-haywire/haywire"
# … and the rest, documented in haybale-toml.md

# A [deprecated] block, when the author declared one, is written LAST in the
# row — it is a table, and TOML parses every bare key after a table header into
# that table. Anything emitted after it would silently join it.
[haybales.deprecated]
since             = "0.0.41"
reason            = "Superseded by haybale-vision."
successor         = "haybale-vision"

[[haybales]]
# One block per library in the project, all bumped to the same version.
name              = "haybale-studio"
version           = "0.0.40"
install_spec      = "haybale-studio @ git+https://github.com/going-haywire/haywire.git@v0.0.40#subdirectory=barn/haybale-studio"
source            = "git"

    A PyPI-published row is shorter — the install spec is a plain requirement and there is no repository to resolve paths against:

    [[haybales]]
name         = "haybale-image"
version      = "1.0.0"
require      = "haywire-core>=0.0.39"
description  = "Image processing nodes for haywire"
source       = "pypi"
install_spec = "haybale-image>=1.0.0"

    Empty and default-valued fields are omitted on write, so a real row is only as long as the library is descriptive.

    Field inheritance¶

    One schema, shared by every [[haybales]] and [[caches]] section wherever they appear. The runtime dataclass is Haybale (haywire.core.marketstall.types).

    haybale — how the field gets into haybale.toml, whose field table defines what each one means. marketstall — how the row field is produced at publish time.

    field haybale marketstall example
    name immutable (mutable only via rename-wizard) copy "haybale-core"
    id immutable (mutable only via rename-wizard) copy — published so a consumer can resolve a registry key before installing "core"
    version canon here; set via share-wizard copy — pyproject.toml carries the generated copy "0.0.40"
    linked_libraries seeded by scaffold; share-wizard maintains copy module names: ["haybale_studio"]
    label user input copy "Core"
    description user input copy "Fundamental components for haywire graphs"
    authors user input (repeatable; name, optional url) copy — repeatable [[authors]] tables, each with an optional url [{name="maybites",url="https://maybites.ch"},{name="cansik"}]
    tags user input copy ["haywire", "node-editor", "core"]
    os user input (multi-select) copy ["macos", "linux"]
    on_reload user input (choice) copy "restart"
    origin regenerated by share-wizard from the git remote copy "https://github.com/going-haywire/haywire"
    origin_provider autofilled by preflight's host check copy "github" / "gitlab"
    homepage_url user input copy "https://github.com/going-haywire/haywire"
    documentation_url user input copy "https://going-haywire.github.io/haywire/"
    issues_url user input copy "https://github.com/going-haywire/haywire/issues"
    examples_path user input; wizard repairs a broken one copy — verbatim, project-relative; verified at preflight "examples/" (from the project root)
    tests_path user input; wizard repairs a broken one copy — verbatim, project-relative; verified at preflight "tests/" (from the project root)
    notes user input; preflight offers the package root's *.md copy — a bare filename inside the package dir "NOTES.md"
    deprecated hand-edited in the file; no modal field copy — also projects into a PyPI classifier {since="0.0.41", reason="…", successor="haybale-vision"}
    require — generated — the haywire-core floor from [project] dependencies "haywire-core>=0.0.31"
    install_spec — generated — {name} @ git+{origin}.git@{tag}#subdirectory={lib_rel} "haybale-core @ git+https://…@v0.0.40#subdirectory=barn/haybale-core"
    source — generated — "git" (wizard) / "pypi" (CI script) / "local" (a row read from a haybale.toml on disk, never published) "git"
    source_label — runtime routing, not persisted —
    source_file — runtime routing, not persisted —
    source_origin — runtime routing, not persisted —
    via — refresh-owned, project [[caches]] only —
    last_seen — refresh-owned, project [[caches]] only —
    stale — refresh-owned, project [[caches]] only —

    Three groups, and the shape of the table is the point:

    • copy — 18 fields pass through untouched. A marketstall row is mostly a verbatim haybale.toml.
    • generated — 3 fields the library cannot state itself: install_spec (name + origin + tag + subdirectory), source, and require (the framework floor projected out of [project] dependencies).
    • not persisted / refresh-owned — 6 fields belonging to the consumer's cache, never written by a publisher.

    Cache-only fields¶

    Never authored upstream; written by refresh into a project's [[caches]] — see marketplace.toml.

    Field Type Notes
    via string URL of the subscription that resolved this row. Drives the provenance label and the Block button
    last_seen string ISO timestamp, set when the row first goes stale
    stale bool True when the latest refresh did not re-resolve this name

    Runtime-only fields¶

    source_label, source_file and source_origin are routing metadata held in memory and never persisted. source_origin records whether a row arrived from a market or a stall, and is unrelated to origin.

    Two fields the marketstall spells differently¶

    Everywhere else "copy" is literal. These two are not:

    haybale marketstall why
    [[authors]] (repeatable, each with an optional url) [[authors]] Copied verbatim, URLs included
    label absent label = title-cased name The marketstall always has something to render; the file may omit it

    Tag pinning¶

    install_spec is pinned to the release tag v<version> only when the row is produced through the full share pipeline, which resolves and collision-checks the version before the write. A standalone write_marketstall() call — CI's generator, or a checkout that never ran the wizard — emits an unpinned spec that floats to the current branch.

    Every other path in the row is repo-relative and resolves against install_spec's ref, so a single ref governs the whole row and the fields cannot disagree about which commit was published. Earlier rows baked absolute raw-content URLs, which let a guessed branch 404 permanently.

    How a consumer resolves a path¶

    Given a row, resolve_row_path() needs three things: origin, a ref, and the declared path.

    1. The host provider comes from origin_provider, falling back to resolve_host(hostname) against built-ins and ~/.haywire/config.toml.
    2. The ref comes from install_spec.
    3. A trailing slash selects the provider's tree URL; otherwise its blob URL.

    Anything unresolvable yields no link rather than a guessed one. An installed library with no row at all — a heap, a barn folder, an editable install — resolves the same coordinates from its own haybale.toml, which carries origin, origin_provider and version.

    Publishing one¶

    uv run haywire share --bump patch     # bump every barn library in lockstep, rewrite this file
uv run haywire share --dry-run        # report what a publish would do; write nothing

    The unit of publishing is the project, not the library: every barn/* library is bumped to the same version and written into one marketstall. The full author flow is in the sharing-libraries guide.

    Consumers subscribe by pasting this file's URL into Add Source — the runtime recognises a blob URL, a raw URL, a plain TOML URL, or a pasted block. See marketplace.toml.
