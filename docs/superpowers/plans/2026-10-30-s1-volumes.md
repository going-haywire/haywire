# S1 — Volumes, volume paths, PATH types and the path picker — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give haywire portable, confined file paths: named **volumes** located per machine, a
`PATH` / `FILE_PATH` / `FOLDER_PATH` type family whose values are `(volume, relative)`, a resolver that
refuses escapes and reports undefined volumes, a path picker widget, an ADMIN Volumes editor and a
`haywire volumes` CLI.

**Architecture:** Volumes are declared Surface-style — a `Volume` subclass with a class-level `name`
registers itself on import into a module-level map (ADR 0009/0029 pattern), never instantiated.
Locations come from `~/.haywire/volumes.toml` first, the declared default second. All of it lives in
`haywire.core.volumes`; the PATH types and the widget live in builtin; the folder tree used by the
picker is moved out of haybale-studio's file browser into a core element both share; the Volumes editor
lives in haybale-studio; the CLI in haywire-studio.

**Tech Stack:** Python 3.12, NiceGUI/Quasar (`ui.tree`, `ui.select`, `ui.input`), tomlkit via
`haywire.core.tomlio`, argparse CLI.

**Spec:** [2026-10-30-spandrel-haybale-design.md](2026-10-30-spandrel-haybale-design.md) — §2.1 (Paths),
amended by Task 1 with the S1 planning decisions below.

## Global Constraints

- A graph stores only `(volume, relative)`; `relative` is a POSIX-style string (`/` separators) kept
  **verbatim** — the resolver interprets it, nothing rewrites it.
- Volume names match `^[a-z][a-z0-9_-]*$`.
- Framework volumes: `project` (= ambient `get_workspace_root()`, `configurable = False`) and `home`
  (= `Path.home()`).
- Resolution order: non-configurable declared volume → its default; else `volumes.toml` entry; else
  declared default; else `VolumeUndefinedError`. Resolving never creates folders.
- Escape refusal is checked on the **resolved** path (`..`, absolute `relative`, outward symlinks) →
  `VolumeEscapeError`.
- Volumes file: `~/.haywire/volumes.toml`, table `[volumes]`, `name = "/absolute/location"`; re-read when
  its mtime changes; written with `haywire.core.tomlio`.
- **Tests never touch the real `~/.haywire/volumes.toml`**: every test uses a `VolumeStore` on
  `tmp_path` installed via `set_volume_store()` (see `.insights/project_tests_wrote_workspace_settings.md`).
- Writing volumes (editor, CLI) is ADMIN: the editor carries `requires=AccessTier.ADMIN`; the CLI runs
  on the server.
- No relative imports under `barn/`. Line length 109. New tests carry `pytestmark = pytest.mark.unit`
  (or `integration` where they boot the library system).
- Docstrings follow `.claude/rules/python-docs.md`; displayed component docstrings (types, widgets,
  editors) are Markdown.

## Review Focus

1. **Windows-style input in `relative`** (`sub\\file.png`, `C:\\x`) — a backslash is a literal character
   on POSIX; an absolute Windows path must still be refused as an escape. → Task 4 test.
2. **Volume location that does not exist yet** (external drive unplugged, `models:` before first
   download) — resolve still returns the path (no error), the picker shows the volume as missing, the
   editor marks it. → Tasks 4, 7, 8 tests.
3. **`volumes.toml` malformed or hand-edited with a bad name / relative location** — the store logs and
   ignores bad entries instead of crashing the studio. → Task 3 test.
4. **Symlink inside a volume pointing outside it** (`models/shared -> /Volumes/Other`) — refused as an
   escape (spec decision), with a message naming the symlinked part. → Task 4 test.
5. **Workspace root changes while running** (project switch) — `project` resolves against the current
   ambient root on every call, never a cached one. → Task 2 test.
