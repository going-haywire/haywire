# Open follow-ups — backlog

What is still open after the editor-modes slices, the follow-up batches of 2026-10-20 to 2026-10-22, and the browser access layer (ADR 0060, 2026-10-24). Landed items have been removed; git history keeps them. ADRs 0051–0060 record the decisions.

This is a backlog, not an executable plan: each item names what is wrong, where, and a suggested first step. Pick one, settle it with the user, then write a plan for it.

Items carry stable IDs (`#N`; handoff notes cite them), so the numbering has gaps. Line references are from the date the item was added.

## 2. Performance

- **#9** **CLOSED** (2026-10-28: squeezed as far as payload cuts go; the Vue full-tree render and ~107 elements per card are accepted. Findings: `.insights/project_browser_rendering_cost.md`) **Drawing large graphs.** The 512-node load went from 23 s to ~12 s (Firefox 52 s → 11 s) on 2026-10-20; the Vue full-tree render walk remains (`.insights/project_browser_rendering_cost.md`). The 11,264 pins are half the bytes (~1.2 KB each). Their server-side hover listeners are gone (2026-10-27: tips drawn in the browser, `haywire.ui.hover_tip`; 26.8 → 22.8 MB, all edges ~1–1.4 s sooner in both engines). Tried and dropped the same day: moving the pins' fixed inline styles (`position`, `cursor`, grid centring) into `canvas.vue` CSS saved 0.85 MB but no time in either engine (A/B within noise), so payload cuts of ~1 MB do not pay; the remaining pin `data-*` attributes (4.2 MB) are unlikely to either. What is left is the Vue full-tree render and the element count (~107 per card).
